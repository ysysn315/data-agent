# 性能容量规划（易混淆文档）

> 本文档讨论的是"性能容量规划"——提前评估资源需求、做预算与扩容计划。注意与"性能故障排查"区分：慢响应/CPU 高时应先读 slow_response.md / cpu_high_usage.md。本文档会被"性能"关键词误召回，是评测刻意设计的 false friend。

## 容量规划流程

1. 以 QPS 峰值 × 预留系数得出目标容量；
2. 压测获得单实例容量基线；
3. 计算所需实例数并加跨机房冗余；
4. 每季度按业务增长滚动修正。

## 与故障排查的关系

容量不足是慢的**可能**根因之一，但排查入口永远是实时指标（system-metrics）而非规划文档。
