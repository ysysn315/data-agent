# 缓存调优手册

## 何时引入缓存

数据库慢查询（slow_query 日志）持续出现、且读多写少的数据，优先考虑缓存而非直接加索引。

## 调优要点

1. **Key 设计**：业务前缀 + 实体 ID，带版本号便于批量失效；
2. **过期策略**：热数据过期时间加随机抖动，防雪崩；
3. **穿透/击穿**：空值缓存 + 单飞（singleflight）加载；
4. **一致性**：先更新库后删缓存，接受短暂不一致的业务才可上缓存。

## 效果验证

上线前后对比 system-metrics 的数据库 QPS 与接口 P99；缓存命中率低于 60% 需回查 Key 设计。

注意：本手册针对数据库读优化；若慢的根因是 SQL 本身，先见 slow_response.md 的数据库层排查。
